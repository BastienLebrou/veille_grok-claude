### 1. Azercosmos lance Platerra, plateforme GeoAI d’analyse d’imagerie satellite
- Date : 7 octobre 2026 (SatNews)
- Résumé : l’opérateur national Azercosmos (Bakou) annonce Platerra, portail qui branche des flux d’observation de la Terre sur des modèles de machine learning pour réduire la photo-interprétation manuelle. Suite annoncée : rehaussement et débruitage optique, détection de couvert forestier et changements de végétation, contours de plans d’eau, détection d’objets et d’infrastructures, délimitation de parcelles et suivi de cultures. Public visé : planification civile, agriculture, gestion environnementale. Extension prévue vers le multi-spectral. Portail : https://platerra.ai/
- Pertinence : ce n’est pas un foundation model publié, c’est un produit opérateur. Utile comme référence de packaging (indices + objets + contours livrés, pas des poids). À comparer à un stack ouvert (STAC + modèle d’extraction) plutôt qu’à adopter tel quel tant que licence, capteurs et AOI ne sont pas documentés.
- Actions :
  1. Ouvrir https://platerra.ai/ et noter accès, couverture géo, capteurs, prix.
  2. Lire le brief SatNews : https://satnews.com/2026/10/07/azercosmos-launches-platerra-ai-platform-for-automated-geospatial-and-satellite-imagery-analysis/

### 2. EmbeddingGemma 2 : embeddings multimodaux ouverts, 740M, Apache 2.0
- Date : 6 octobre 2026 (Google Developers Blog / blog.google)
- Résumé : Google sort EmbeddingGemma 2, modèle ouvert Apache 2.0 fondé sur Gemma 4. Il projette texte, code, images, vidéo et audio dans un espace commun de 768 dimensions. Architecture modulaire : 270M (texte/code), 440M (texte+vision), jusqu’à 740M complet. Contexte texte 8 192 tokens, >100 langues. Matryoshka : troncature 128 / 256 / 512 / 768 (jusqu’à ~6× moins de stockage). Empreinte annoncée ~191 Mo RAM (texte quantifié) à ~567 Mo (multimodal) sur Pixel 11 Pro. Gain code MTEB cité : 68,76 → 78,68.
- Pertinence : ce n’est pas un GeoFM (pas de Sentinel / SAR). En géomatique, c’est un index local pour tuiles, captures terrain, PDF de plans et légendes, sans envoi cloud. Complète AlphaEarth / TESSERA (empreintes annuelles de lieu) par une recherche cross-modale « image ↔ texte » là où on a des vignettes ou des orthos déjà découpées. Ne remplace pas un modèle spectral.
- Actions :
  1. Lire https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2/ et https://ai.google.dev/gemma/docs/embeddinggemma
  2. Tirer le checkpoint Hugging Face et embedder 50 tuiles + leurs légendes ; mesurer le rappel d’une requête du type « toiture claire près d’un plan d’eau ».
  3. Tester la troncature 256-D avant de dimensionner une base vecteur.

### 3. Perplexity pplx-embed-v2-late : late-interaction multimodale, MIT, 0,6B et 9B
- Date : 7 octobre 2026 (annonce ; reprises MarkTechPost / i10x le 7–8)
- Résumé : deux modèles ColBERT-like, poids MIT sur Hugging Face. Ils gardent un vecteur de 128 dimensions par token et scorent en MaxSim, au lieu d’un seul vecteur par page. Ils lisent texte, images et pages PDF rendues, sans OCR. Espace partagé : indexer avec le 9B, requêter avec le 0,6B (~240M actifs en texte, ~340M en image, ~1,2 Go bf16). Chiffres Perplexity (non indépendants) : MADQA 90,1 % (0,6B) / 92,4 % (9B). API hébergée annoncée, pas encore en ligne.
- Pertinence : cas direct = fonds de cartes scannées, rapports d’étude, CCTP, slides d’AO, là où l’OCR casse les tableaux et les légendes. Le couple 9B index / 0,6B requête colle à un SIG qui indexe la nuit et interroge sur poste. Coût stockage plus élevé qu’un embedding dense (multi-vecteurs).
- Actions :
  1. Lire https://www.marktechpost.com/2026/10/07/perplexity-ai-releases-pplx-embed-v2-late-a-0-6b-edge-model-and-a-9b-model-scoring-92-4-on-madqa/
  2. Chercher `pplx-embed-v2-late` sur Hugging Face ; indexer 20 PDF de plans avec le 0,6B seul d’abord.
  3. Comparer sur 10 questions à un pipeline OCR + EmbeddingGemma 2 : qualité vs coût disque.

### 4. Claude Haiku 5.5 : palier agent pas cher pour les outils SIG
- Date : 7 octobre 2026 (Anthropic ; dispo Bedrock)
- Résumé : Haiku 5.5 remplace Haiku 4.5 comme modèle rapide de la famille Claude 5.5, avec contrôle d’effort. Prix cités ~0,10 / 0,50 USD par million de tokens entrée / sortie sous 100k, puis 0,50 / 2,50 au-delà ; AWS évoque environ −75 % vs Haiku 4.5 sur la plupart des tâches. Artificial Analysis le place 2e/182 de sa classe (score 43), en notant une conso de tokens élevée. Même jour : Mistral Large 4 (« Le Chonk »), preview API, 1 T paramètres / 49 Md actifs, poids promis fin octobre — moins prioritaire ici (pas de gain géo spécifique, score AA mixte).
- Pertinence : les agents géospatiaux (STAC, band math, géocodage) sont limités par le coût du tour d’outil, pas par la taille du modèle. Haiku 5.5 est le candidat à brancher sur le sample AWS déjà noté le 7 oct., ou sur un agent local d’outils. Mistral Large 4 reste un watch « poids ouverts fin octobre », pas une action du jour.
- Actions :
  1. Fiche Anthropic / Bedrock Haiku 5.5 ; tracker https://benchlm.ai/model-updates/releases/october-2026
  2. Rejouer un enchaînement géocode → STAC → NDVI en comparant Haiku 5.5 et le modèle déjà en place (coût, tours, erreurs d’outil).
  3. Noter fin octobre pour les poids Mistral Large 4 ; ne pas prototyper dessus tant que l’API preview est le seul accès.
