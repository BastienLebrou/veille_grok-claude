## Points (qualité > quantité)

### 1. ArcGIS Earth 3.0 : couches Gaussian splat géoréférencées
- Date : billet Esri 1er octobre 2026 ; reprise Radiance Fields 2 octobre
- Résumé : ArcGIS Earth 3.0 (desktop) affiche des Gaussian splat layers géoréférencés dans des Local Scenes, à côté du terrain, de l’imagerie, des bâtiments et des données opérationnelles. Les scènes locales et les 3D Building Layers arrivent aussi sur mobile ; les splats restent desktop. SDK sous-jacent : ArcGIS Maps SDK for .NET 300.1 (splats déjà dans Pro 3.6 / Scene Viewer Enterprise 12.1). Points ouverts : splats en scène globale ? archives .3tz offline ?
- Pertinence : le Gaussian splat sort du viewer 3D isolé et entre dans le SIG de terrain (AEC, sécurité, réseaux). C’est le maillon visualisation du pipeline capture (drone / Scaniverse / photogrammétrie) → reconstruction → couche interrogeable. Utile là où le mesh échoue (végétation, verre, structures fines).
- Actions :
  1. Lire https://www.esri.com/arcgis-blog/products/arcgis-earth/3d-gis/whats-new-in-arcgis-earth-october-2026 et https://radiancefields.com/esri-adds-gaussian-splat-layers-to-arcgis-earth-3.0
  2. Tester Earth desktop (gratuit) avec un splat géoréférencé sur un site connu ; noter le CRS et l’alignement terrain.
  3. Use-case : QA visuel d’un nuage LiDAR / mesh vs splat sur végétation et câbles, avant d’automatiser la détection.

### 2. GeoAgent (IJGIS) : architecture multi-agents hiérarchique pour l’analyse spatiale
- Date : page Taylor & Francis indexée le 3 octobre 2026 (article en ligne depuis le 16 février 2026, IJGIS vol. 40 n°10, p. 3343–3382) — paper, pas un produit
- Résumé : GeoAgent sépare planification, exécution d’outils SIG et revue. Trois toolsets (perception d’environnement, insight data). Sur 147 tâches d’analyse spatiale : 94,56 % de succès avec GPT-4o, 95,24 % avec DeepSeek-V3. L’ablation montre que les couches Planning et Review sont décisives pour l’intégrité du workflow.
- Pertinence : cadre de référence académique pour les agents SIG déjà vus (MCP, Kermit, GAIA). Le chiffre utile n’est pas le taux brut mais l’ablation : sans revue, les agents spatiaux cassent sur les tâches composées. À croiser avec l’alerte qualité de Cercana (2 oct.) : 15/22 soumissions GeoAI d’été (NeurIPS, WACV, TerraBytes/ECCV) contenaient citations fabriquées ou texte machine.
- Actions :
  1. Lire l’abstract et le design des couches : https://www.tandfonline.com/doi/full/10.1080/13658816.2026.2624784
  2. Recopier le pattern Planning + Review dans tout prototype agent (log d’outils, vérif géométrie/CRS avant restitution).
  3. Vérifier manuellement les citations avant de citer un paper GeoAI 2026.

### 3. Google Earth Engine : assistant IA dans le Code Editor
- Date : reprises presse 28–29 septembre 2026 (bord extérieur de la fenêtre, absent des briefs précédents)
- Résumé : le Code Editor GEE intègre un assistant qui génère, debugge et optimise des scripts JavaScript ou Python à partir d’un prompt (filtrer une collection, NDVI sur une région et une saison, adapter un script à un shapefile). Données visées : Landsat, Sentinel, MODIS.
- Pertinence : même thèse que les agents SIG, mais sur le runtime planétaire déjà adopté. Le risque opérationnel est le script plausible mais faux (mauvaise échelle, double comptage temporel, CRS implicite). À traiter comme un générateur de brouillon, pas comme un analyste.
- Actions :
  1. Dans un projet GEE, demander un NDVI saisonnier sur une zone connue et diff le script avec une version écrite à la main.
  2. Ajouter une checklist de revue : scale, reducer, masque nuages, système de projection, unités.
  3. Ne pas enchaîner cet assistant avec un agent de tasking sans garde-fou humain.

### 4. EarthPV : foundation model ouvert pour cartographier le photovoltaïque
- Date : annonce webinaire Open Energy Transition, 2 octobre 2026
- Résumé : EarthPV cartographie le PV avec un foundation model géospatial ouvert, de l’imagerie et des jeux libres (pas d’imagerie commerciale propriétaire). Cas d’étude Pakistan. Webinaire Eventbrite : https://www.eventbrite.com/e/mapping-photovoltaics-earthpv-methodology-results-on-pakistan-case-study-tickets-2002496276268
- Pertinence : contre-exemple utile au stack « insight only » commercial (Altair, tasking MCP). Montre qu’un FM ouvert + Sentinel suffit pour un inventaire d’actifs énergie, à condition de publier méthode et erreurs. Bon banc d’essai pour comparer embeddings TESSERA vs un détecteur spécialisé.
- Actions :
  1. S’inscrire ou récupérer les slides du webinaire ; chercher le dépôt / papier EarthPV.
  2. Sur une commune connue, comparer détection PV open vs cadastre / OSM.
  3. Suivre @OETenergy pour le lien méthodo.
