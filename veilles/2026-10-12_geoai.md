## 1. Azercosmos lance Platerra : plateforme IA pour l’analyse automatisée d’imagerie satellitaire

**Résumé**  
Le 7 octobre 2026, Azercosmos a annoncé le lancement de **Platerra**, une plateforme IA qui automatise le traitement d’imagerie satellite (amélioration, détection de forêts, eaux de surface, objets/infrastructure, délimitation de parcelles agricoles). Accessible via [platerra.ai](https://platerra.ai/).  
Sources : SatNews, Via Satellite.

**Pertinence**  
Exemple concret d’industrialisation du GeoAI « vertical » (CV classique sur EO) pour des cas d’usage opérationnels (agriculture, environnement, ressources). Montre que les opérateurs satellitaires poussent désormais leurs propres couches d’analyse.

**Actions recommandées**  
1. Tester le portail public platerra.ai (si accessible) sur une zone d’intérêt.  
2. Comparer les outputs avec des pipelines open-source (ex. : Segment Anything + post-traitement ou Prithvi/AlphaEarth).  
3. Réfléchir à un use-case local (suivi végétation / eau) où une solution clé-en-main gagne du temps.

## 2. Google Earth AI et AlphaEarth Foundations : embeddings planétaires et applications santé / classification

**Résumé**  
Google continue de déployer **Google Earth AI** (collection de modèles et datasets géospatiaux). AlphaEarth Foundations produit des embeddings annuels à 10 m (2017+) disponibles dans Earth Engine. Récents développements : applications santé publique (prévision maladies via embeddings + agents de raisonnement), outil de classification no-code dans Google Earth, et papiers d’extension (ex. eau de surface Sentinel-1 + embeddings).  
Sources : blog Google, arXiv, Earth Engine.

**Pertinence**  
Les embeddings sont devenus la « couche d’abstraction » dominante du GeoAI. Ils permettent classification, recherche de similarité et fine-tuning à faible coût, et s’intègrent dans des agents. AlphaEarth est désormais un standard de facto pour beaucoup de workflows.

**Actions recommandées**  
1. Explorer le dataset `GOOGLE/SATELLITE_EMBEDDING/V1/ANNUAL` dans Google Earth Engine.  
2. Tester l’outil de classification dans Google Earth (web).  
3. Lire un paper récent d’application (ex. surface water avec AlphaEarth embeddings).

## 3. Microsoft MARS : extraction native de features vectorielles (bâtiments, routes, eau) depuis l’imagerie

**Résumé**  
**MARS** (Map Autoregressive Transformer) convertit directement des tuiles satellitaires/aériennes en GeoJSON vectoriel (polygones bâtiments/eau, lignes routes/rails) sans passer par des masques raster + post-traitement. Disponible via Microsoft Foundry / Planetary Computer.  
Sources : Microsoft Foundry, Tech Community, mentions X récentes.

**Pertinence**  
Changement de paradigme : sortie native vectorielle de qualité GIS, prête à charger dans QGIS/ArcGIS. Réduit les erreurs de vectorisation et accélère la production de cartes. Idéal pour mise à jour de réseaux ou bâti.

**Actions recommandées**  
1. Consulter la doc et le notebook MARS sur Planetary Computer Pro / Foundry.  
2. Tester sur une zone NAIP ou équivalent haute résolution.  
3. Comparer qualité/temps avec un pipeline segmentation + vectorisation classique.

## 4. GeoNatureAgent (GNA) et émergence des benchmarks d’agents géospatiaux via MCP

**Résumé**  
Paper arXiv (6 oct. 2026) : **GeoNatureAgent** propose un framework + benchmark (103 tâches) pour évaluer des agents LLM utilisant des outils géospatiaux exposés via MCP. Claude Sonnet 4 et DeepSeek V3.2 en tête ; code et MCP server publics.  
En parallèle, GIS Cloud (et d’autres) exposent leurs APIs via MCP pour Claude/ChatGPT.

**Pertinence**  
Le passage « modèle → agent qui orchestre des outils GIS » est le vrai levier d’adoption. MCP est devenu le standard d’interconnexion. Évaluer la fiabilité des agents avant production est critique.

**Actions recommandées**  
1. Lire le paper : https://arxiv.org/abs/2610.09112  
2. Explorer le repo / MCP server associé.  
3. Tester une connexion MCP (GIS Cloud, ArcGIS Location Services, ou un serveur open-source) avec Claude ou un agent local.

## 5. Anaximander : lancer des modèles de deep learning géospatial de façon interactive dans QGIS (tous backends)

**Résumé**  
Paper + système open-source (Microsoft + collaborateurs) : **Anaximander** permet de charger des modèles (local, GPU distant, API cloud) et de les exécuter interactivement depuis QGIS (tuilage, géoréférencement, visualisation temps réel). Démo sur délimitation de parcelles agricoles. Repo : https://github.com/microsoft/nxmndr  
Source : arXiv 2610.09085, mentions récentes.

**Pertinence**  
Réduit la friction majeure entre praticiens GIS et modèles foundation/CV. Permet comparaison code-free de modèles hétérogènes.

**Actions recommandées**  
1. Cloner le repo microsoft/nxmndr et suivre le README.  
2. Installer le plugin QGIS associé et tester un modèle simple (SAM ou un modèle EO).  
3. Évaluer si cela peut remplacer des scripts custom pour l’inférence tuilée.
