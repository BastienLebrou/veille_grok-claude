## 1. RustGIS v0.1 / v0.2 : GIS desktop + web en Rust pur avec Assistant IA et serveur MCP

**Résumé**  
Open Geospatial Solutions (Qiusheng Wu / @giswqs) a publié RustGIS v0.1.0 le 12 octobre et v0.2.0 le 13 octobre 2026. C’est un GIS complet écrit en Rust pur (binaire léger 18-30 Mo), qui tourne en desktop (Windows/macOS/Linux) et dans le navigateur (web.rustgis.app). Il gère GeoJSON, Shapefile, GeoPackage, GeoParquet, FlatGeobuf, GeoTIFF/COG, PMTiles, etc., avec >1 000 outils de géotraitement (GeoLibre + Whitebox), ModelBuilder, layouts, et un Assistant IA intégré. L’assistant (Anthropic, OpenAI, Gemini, Ollama, etc.) exécute des commandes sur la carte (chaque action est undoable). Point clé : un serveur MCP (`rustgis-cli mcp`) permet à des agents externes (Claude Code, Cursor, VS Code, Codex) de piloter entièrement le GIS (ouvrir des données, lancer des outils, rendre des cartes). Données restent locales sauf si envoyées à un modèle choisi.

**Pertinence**  
Premier GIS open-source moderne pensé nativement pour les agents. Au lieu d’un plugin AI dans QGIS/ArcGIS, c’est un outil scriptable de bout en bout + MCP. Idéal pour prototyper des workflows agentiques, intégrer dans des pipelines Claude/Cursor, ou remplacer des chaînes manuelles. Montre la direction « GIS comme backend d’agent » plutôt que « chatbot dans le GIS ».

**Actions recommandées**  
1. Essayer immédiatement la version web : https://web.rustgis.app (aucun install) ou télécharger le binaire (https://downloads.rustgis.app / GitHub opengeos/RustGIS).  
2. Activer l’Assistant IA avec un modèle local (Ollama) ou cloud et lui demander de charger un GeoJSON + buffer + symbologie.  
3. Brancher le MCP dans Claude Desktop / Cursor (`claude mcp add rustgis -- rustgis-cli mcp --sample`) et tester une requête spatiale end-to-end.

## 2. Paper arXiv : « The Last Remote Sensing Model Built by Humans? » – agents qui construisent et auto-améliorent les modèles EO

**Résumé**  
Paper soumis le 13 octobre 2026 (v2 le 15), arXiv:2610.18845 par Sijie Zhao, Zhuo Zheng, Naoto Yokoya et al. L’idée : au lieu que des experts conçoivent manuellement chaque modèle de télédétection, on définit seulement un *harness* (ce que l’agent peut utiliser) et un *verifier* (ce qui constitue le succès). Un agent de coding généraliste construit alors le modèle et l’améliore récursivement sur ses propres sorties. Sur six benchmarks EO (optique, SAR, séries temporelles multispectrales — land-cover, détection de bateaux, hauteur de canopée, etc.), les modèles construits par agent dépassent le SOTA, et sur le land-cover ils y parviennent avec seulement 11 % des labels d’entraînement. Paradigme : les humains conçoivent les harnesses/verifiers, les agents construisent les modèles.

**Pertinence**  
Potentiellement transformateur pour la recherche et la production de modèles GeoAI. Réduit drastiquement le temps et l’expertise nécessaires pour adapter un modèle à une nouvelle tâche ou un nouveau domaine. Complète parfaitement les agents de raisonnement (Google GRA, OpenEarthAgent) en s’attaquant à la couche « construction de modèle » plutôt qu’à l’inférence/orchestration.

**Actions recommandées**  
1. Lire l’abstract et le paper : https://arxiv.org/abs/2610.18845 (PDF/HTML disponibles).  
2. Identifier 1-2 tâches EO de votre quotidien qui pourraient être reformulées en harness + verifier (ex. détection de changement avec labels limités).  
3. Surveiller le code/résultats associés (projet en cours) et tester des agents de coding (Claude, Cursor, Aider) sur un mini-benchmark EO local.

## 3. Hesai Kosmo (rappel opérationnel) + convergences capture 3D pour IA physique

**Résumé**  
Suite à l’annonce du 14 octobre, Hesai détaille Kosmo One (caméra spatiale 8K + LiDAR 1535 nm intégré, IMU, sync microseconde) + Kosmo World (reconstruction 3D Gaussian Splatting + mesh + depth, précision millimétrique). Scan de ~100 m² en 15 min par un opérateur ; sortie directement utilisable pour entraînement de robots (ex. 99 % de succès sur tâche réelle) et world models. Intégrations NVIDIA Isaac, Unreal, etc. Positionné comme infrastructure de données pour l’embodied AI.

**Pertinence**  
La capture terrain haute fidélité devient une commodité pour alimenter l’IA physique. Pour les praticiens GIS/LiDAR/drones, cela ouvre des cas d’usage au-delà de la cartographie : production de données d’entraînement synthétiques/réelles hybrides, digital twins interactifs, etc.

**Actions recommandées**  
1. Consulter le site Hesai et les articles (Reuters, Radiance Fields) pour les specs exactes de capture/reconstruction.  
2. Expérimenter localement des pipelines Gaussian Splatting (Nerfstudio, gsplat, etc.) sur vos propres scans LiDAR/drone pour mesurer le gap avec Kosmo.  
3. Réfléchir à un use-case interne où un digital twin 3D haute fidélité améliorerait un workflow robotisé ou de simulation.
