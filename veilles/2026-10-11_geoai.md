## Points (qualité > quantité)

### 1. Microsoft MARS : extraction vectorielle native (bâtiments, routes, etc.) depuis l’imagerie
- Date : modèle disponible sur Microsoft Foundry ; mise en avant X ~8 oct. 2026 (Milan Janosov et al.)
- Résumé : Map Autoregressive Transformer (MARS) génère directement des features GeoJSON vectorielles (polygones bâtiments, polylines routes/railways, eau) à partir de tuiles satellite/aériennes, sans post-processing raster classique. Architecture Geoformer + décodage autoregressif. Entraîné sur MAP-3M (~3,4 M exemples NAIP). Outputs attribués avec confidences. Disponible via GeoAI SDK / Planetary Computer Pro.
- Pertinence : Change le paradigme de « segmentation pixel → vectorisation » vers génération vectorielle end-to-end. Accélère la production de cartes à jour et s’intègre dans pipelines GIS. Intéressant pour comparer à SAM + post-processing ou à d’autres extracteurs.
- Actions :
  1. Lire la doc / blog Microsoft : https://techcommunity.microsoft.com/blog/microsoft-planetary-computer-blog/ai-enabled-map-production-using-microsofts-mars-model/4542498 et explorer le catalog Foundry.
  2. Tester via le SDK GeoAI si accès Azure, ou chercher démos / notebooks publics.
  3. Use-case : extraire bâtiments + réseau sur une AOI locale et comparer qualité / coût à un pipeline open (ex. Segment Anything + vectorisation).

### 2. GeoSeg-OV : segmentation open-vocabulary pour télédétection
- Date : paper arXiv août 2026 (2608.10426) ; relais Geoawesome / X ~8 oct.
- Résumé : Framework qui permet la segmentation pixel-level de catégories décrites en langage naturel (y compris classes non vues à l’entraînement). Découple features VFM pour guidance structurelle + CLIP multi-rotation pour coût volume. Benchmark HRLC (7 datasets, 6 continents, >90 villes). Gains +2,5 / +2,7 mIoU moyen vs SOTA.
- Pertinence : Ouvre la porte à des requêtes flexibles (« segmenter les toitures solaires » ou « zones inondées récentes ») sans ré-entraînement lourd. Complémentaire aux foundation models et agents.
- Actions :
  1. Lire le paper : https://arxiv.org/abs/2608.10426 et l’article Geoawesome https://geoawesome.com/geoseg-ov-open-vocabulary-remote-sensing/
  2. Chercher code / poids si publiés ; sinon prototyper une version simple avec CLIP + SAM ou open-vocab existants.
  3. Réfléchir à un use-case d’inventaire dynamique (végétation, infrastructures, risques) sur imagerie haute résolution.

### 3. TESSERA embeddings : couverture globale wall-to-wall disponible sur AWS Open Data
- Date : annonces continues sept.-oct. 2026 (AWS blog 29 sept., geotessera 0.11 ~début oct., registry Open Data)
- Résumé : Embeddings 128-dim, 10 m, annuels (2017-2025) fusionnant Sentinel-1 + Sentinel-2 pour chaque pixel terrestre. Produits par Cambridge / dClimate / Arbol. Accessibles via geotessera (Python), Zarr / Icechunk sur S3 (pas d’egress coûteux). Label-efficient pour land cover, change, carbon, agri, etc.
- Pertinence : Foundation model open et prêt à l’emploi qui réduit drastiquement le coût d’entrée pour l’analyse EO temporelle. Base idéale pour fine-tuning léger ou agents.
- Actions :
  1. Installer geotessera et télécharger / streamer une tuile locale : https://geotessera.readthedocs.io/ + https://registry.opendata.aws/tessera/
  2. Tester un downstream simple (classification land cover ou change detection) sur embeddings.
  3. Suivre Anil Madhavapeddy / dClimate pour les mises à jour v1.1 / v2.
