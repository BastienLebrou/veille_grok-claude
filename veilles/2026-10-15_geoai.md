## 1. Google Earth AI : Geospatial Reasoning Agent (GRA) et Planetary Prediction

**Résumé**  
Le 14 octobre 2026, Google Research a publié un technical report et un blog sur son Geospatial Reasoning Agent (GRA). Cet agent, alimenté par Gemini, orchestre les foundation models Earth AI (Remote Sensing Foundations, AlphaEarth, Population Dynamics Foundation Model, WeatherNext, Flood Forecasting…), Google Earth Engine, Maps Platform, Data Commons, etc.  
Il réalise une planification upfront, décompose les requêtes complexes en workflows multi-étapes, et gère un workspace spatial. Évaluations sur de nouveaux benchmarks (GeoExpertQueries, GeoKTools) montrent qu’il surpasse largement les LLM seuls ou avec outils basiques, notamment sur des problèmes ouverts.  
Tests réels avec WHO AFRO (cartographie risque Ebola en RDC en minutes), Milken Institute, People in Need, etc. Extension d’accès expérimental via Ask Google Earth et API agent-to-agent (A2A). Le Planetary Prediction Engine permet d’entraîner automatiquement des modèles prédictifs à partir de données locales.  
Sources : research.google/blog (14 oct.), arXiv:2610.15750, posts @GoogleResearch / @NewsFromGoogle.

**Pertinence**  
C’est l’un des déploiements les plus avancés d’agents géospatiaux multi-modaux et multi-étapes à l’échelle planétaire. Il illustre la valeur des outils spécialisés + planification vs LLM générique, et ouvre la voie à des workflows d’analyse complexe (santé, climat, crise) accessibles en langage naturel. Impact potentiel fort sur la démocratisation de l’analyse spatiale avancée.

**Actions recommandées**  
1. Lire le blog Google Research et le paper arXiv:2610.15750 (focus sur les ablations outils vs planification).  
2. Remplir le formulaire d’intérêt pour early access Ask Google Earth / A2A si pertinent pour vos use-cases.  
3. Réfléchir à un use-case interne où un agent similaire (même avec outils open-source) pourrait réduire le temps d’analyse de jours à minutes.

## 2. Anaximander : exécution interactive de modèles DL géospatiaux dans QGIS (open-source)

**Résumé**  
Paper arXiv:2610.09085 (soumis ~6 oct., visible récemment) présente Anaximander, un système open-source de Microsoft AI for Good. Un serveur d’inférence charge des modèles depuis diverses sources (PyTorch, ONNX, Hugging Face, APIs cloud) et les sert sur n’importe quel backend compute (local CPU/GPU, remote GPU, cloud).  
Un plugin QGIS gère le tiling, le georeferencing, la réassemblage des résultats et une visualisation live par tuile. Supporte aussi des prompts VLM basés sur les légendes de couches. Démo code-free de comparaison de modèles (SAM3, DelineateAnything, gpt-image-1) sur délimitation de champs.  
Code : https://github.com/microsoft/nxmndr.  
Sources : arXiv:2610.09085, Microsoft Research.

**Pertinence**  
Réduit drastiquement la friction pour tester et déployer des modèles de deep learning (foundation models, segmentation, etc.) directement dans l’environnement GIS que les praticiens utilisent déjà (QGIS). Permet des comparaisons systématiques et des workflows interactifs sans code lourd.

**Actions recommandées**  
1. Cloner le repo microsoft/nxmndr et tester le plugin QGIS sur une image satellite de votre choix.  
2. Comparer Anaximander avec d’autres plugins (ex. IAMAP) pour des tâches de feature extraction.  
3. Envisager de l’utiliser pour prototyper rapidement des pipelines d’inférence sur données Sentinel ou drones.

## 3. GeoNatureAgent (GNA) : framework et benchmark MCP pour agents géospatiaux environnementaux

**Résumé**  
Paper arXiv:2610.09112 (6 oct.) introduit GeoNatureAgent, un framework d’évaluation pré-production pour agents tool-using. Interface fixe de 16 outils publiée en serveur MCP, benchmark de 103 tâches (18 catégories) sur indicateurs environnementaux Espagne/Portugal (API open self-hostable).  
Claude Sonnet 4 ~61,7 %, DeepSeek V3.2 proche à coût bien inférieur. Le gap avec des benchmarks GIS plus généraux s’explique en partie par la strictesse du scoring et la réalisme des APIs. Code et API publics : github.com/gabrielireland/GeoNatureAgent_Benchmark.  
Sources : arXiv:2610.09112, repo GitHub.

**Pertinence**  
Fournit un outil concret et reproductible pour choisir et évaluer des LLMs dans des workflows d’agents géospatiaux réels (tool calling, multi-turn, gestion d’erreurs). Particulièrement utile pour des applications environnementales, monitoring, ou pour valider des agents avant production.

**Actions recommandées**  
1. Explorer le repo GeoNatureAgent_Benchmark et lancer un test local sur un petit sous-ensemble de tâches.  
2. Comparer les performances Claude vs DeepSeek (ou modèles locaux) sur votre propre stack MCP.  
3. Adapter le framework à un domaine spécifique (ex. LiDAR, drones, open data française) si vous évaluez des agents.

## 4. Continuité et contexte : école IEEE GRSS, private AI et outils vectoriels

**Résumé**  
L’IEEE GRSS School on Earth Observation and GeoAI for Climate-Resilient Urban Systems se déroule du 14 au 16 octobre 2026 à Linz (Autriche) : labs pratiques sur Sentinel/Landsat/SAR + outils open-source pour risques urbains (chaleur, inondations, subsidence).  
Autres éléments récents : croissance des outils AI dans GIS Cloud (prompts + MCP/ChatGPT/Claude), plateforme Platerra (Azercosmos) pour analyse automatisée d’imagerie satellite, et discussions autour de MARS (Microsoft) pour génération directe de vecteurs GeoJSON (bâtiments, routes, etc.) à partir d’imagerie.  
Sources : SpaceAgenda, GIS Cloud, SatNews, blogs Microsoft Planetary Computer.

**Pertinence**  
Montre la maturation multi-fronts : formation pratique, plateformes commerciales accessibles, et modèles spécialisés qui simplifient le passage raster → vector. Utile pour rester à jour sur les compétences et les outils opérationnels.

**Actions recommandées**  
1. Suivre les retours ou matériaux de l’école IEEE GRSS (si accessibles) pour des cas d’usage urbains.  
2. Tester MARS via Microsoft Foundry / Planetary Computer si vous avez besoin d’extraction de features vectorielles.  
3. Évaluer GIS Cloud AI ou des alternatives MCP pour démocratiser l’accès aux données spatiales dans votre organisation.
