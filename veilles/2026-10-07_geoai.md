## Points (qualité > quantité)

### 1. PDFM (Google Earth AI) : embeddings de lieu plug-and-play pour la santé publique
- Date : preprint arXiv:2610.05699 soumis le 5 octobre 2026 ; billet Google Research le 6 octobre 2026
- Résumé : Google Research publie cinq études partenaires autour du Population Dynamics Foundation Model (PDFM), composant de Google Earth AI. Le modèle compresse, sans fine-tuning spécifique, des signaux agrégés et présentés comme privacy-preserving — tendances de recherche, densité / fréquentation du bâti, mobilité, météo et qualité de l’air — en empreintes de lieu rafraîchies mensuellement. Ces embeddings sont branchés sur des modèles épidémiologiques existants, pas un pipeline neuf. Résultats cités : +36 % de variance expliquée sur la couverture vaccinale ROR dans 146 comtés frontaliers USA–Canada (0,159 → 0,216) ; nowcast mortalité cardiovasculaire comparable au recensement (MAE 18,7 vs 19,1 décès/comté) ; gain significatif à 1 mois sur la dengue municipale au Mexique (jusqu’à 72 % des communes en transmission active) ; +9,7 % AUPRC à 4 semaines et +18,1 % Precision@5 à 8 semaines sur le choléra en RDC ; gain AUC faible mais transférable sur la dépression post-partum (+0,0020 / +0,0038). Une reprise presse du 6 oct. indique que les embeddings sont en Preview commerciale sous le nom Population Dynamics Insights sur Google Maps Platform.
- Pertinence : c’est le pendant « lieu / population » des embeddings pixels (TESSERA, AlphaEarth, Prithvi). Pour un praticien GeoAI, le pattern utile n’est pas le cas d’usage santé en soi, mais l’idée d’injecter une empreinte de lieu mensuelle dans un modèle métier déjà en place (risque, interpolation, nowcast) là où le recensement ou l’enquête a 1–2 ans de retard. Limite assumée par les auteurs : ça ne remplace pas les données individuelles socio-économiques.
- Actions :
  1. Lire le billet https://research.google/blog/earth-ais-planetary-geospatial-foundation-models-for-global-public-health/ puis le preprint https://arxiv.org/abs/2610.05699 (41 p., tableaux de validation).
  2. Vérifier l’accès Preview « Population Dynamics Insights » sur Google Maps Platform et noter la maille, la fraîcheur et la licence avant tout prototype.
  3. Use-case : sur une zone où un indicateur officiel est en retard (couverture, exposition, demande), tester si un embedding de lieu (PDFM si accessible, sinon TESSERA ou AlphaEarth) améliore un nowcast simple — et documenter ce qu’il n’explique pas.

### 2. Sample AWS : agent langage naturel sur Sentinel-2 (NDVI / NDWI / NBR)
- Date : circulation récente (reprise X début octobre 2026) ; pas de tag de release daté dans la fenêtre — à traiter comme outil disponible, pas comme annonce du jour
- Résumé : le repo `aws-samples/sample-geospatial-agent-on-aws` décrit un agent (Strands + Claude Sonnet 4.6 sur Bedrock AgentCore) qui géocode, récupère un contour OSM, tire du Sentinel-2, calcule NDVI / NDWI / NBR et affiche le résultat sur une carte MapLibre. Déploiement annoncé ~15 min (agent + tuiles + frontend React). Un second sample, `sample-geospatial-code-agent`, fait écrire et exécuter du Python (STAC Element 84, Sentinel-2 et Landsat en COG) à partir d’un polygone dessiné. Exemples : santé de végétation à Central Park, sévérité de feu, comparaison de plans d’eau.
- Pertinence : complète le radar Element 84 (2 oct., déjà hors fenêtre stricte) qui faisait passer les interfaces chat géospatiales de Trial à Adopt, et leur agent Limner. Ici le code est public, mais le coût est Bedrock, pas un modèle local. Utile comme référence d’architecture (outils STAC + band math + carte) plutôt que comme stack à copier telle quelle.
- Actions :
  1. Lire https://github.com/aws-samples/sample-geospatial-agent-on-aws (outils : search_places, find_location_boundary, get_rasters, run_bandmath, display_visual).
  2. Si pas de compte AWS : reproduire le même enchaînement en local avec stackstac / odc-stac + un petit LLM, sur une AOI déjà connue, pour comparer la qualité du NDVI « agent » vs un script figé.
  3. Ne pas confondre avec TESSERA : ici ce sont des indices spectraux classiques, pas des embeddings annuels 128-D.

### 3. PalmQ10 (atelier QGIS UC, 6 oct.) : LES urbaine dans QGIS — signal adjacent
- Date : 6 octobre 2026, 15:30–16:00, QGIS User Conference (pretalx)
- Résumé : PalmQ10 est présenté comme un workflow / concept de plugin QGIS open source qui enchaîne domaine de simulation, téléchargement de jeux globaux, prétraitement, exécution PALM (LES) et cartes. Cas d’étude Ciutat Vella (Valence), comparaison à des mesures in situ de chaleur extrême. Pas de modèle d’IA dans le résumé.
- Pertinence : rappelle que le goulet urbain reste souvent l’intégration SIG ↔ modèle physique, pas le foundation model. Utile si un use-case chaleur / morphologie est en cours : le plugin peut servir de baseline physique avant d’y coller un embedding.
- Actions :
  1. Ouvrir https://talks.osgeo.org/qgis-uc2026/talk/EULHKR/ et noter si un repo est lié après l’atelier.
  2. Ne pas le classer GeoAI tant qu’il n’y a pas de modèle appris dans la chaîne.
