## 1. KAIST GeoCore-9B : premier foundation model génératif EO natif à 9B params (NeurIPS 2026)

**Résumé**  
Le 20 octobre 2026, KAIST a annoncé GeoCore-9B, un modèle génératif de 9,24 milliards de paramètres entraîné *from scratch* exclusivement sur des données Earth Observation (dataset Git-10M : 10 millions de paires image-texte satellite + métadonnées géospatiales continues : GSD, lat/lon). Architecture Flow Matching DiT. Il conditionne nativement sur texte + géométadonnées. Applications démontrées : cloud removal (SOTA sur datasets publics), SAR-to-optical translation (images radar → photo-like), et génération. Accepté à NeurIPS 2026. Code, weights et project page disponibles (GitHub KAIST-VICLab/GeoCore-9B, Hugging Face). Paper : arXiv:2608.01896 (publié août, annonce publique 20 oct.).

**Pertinence**  
Marque un pas important vers des priors génératifs vraiment « geo-aware » plutôt que des fine-tunes de modèles naturels (qui introduisent des biais de perspective). Très utile pour le pré-traitement d’imagerie (nuages, nuit, SAR), la synthèse de données d’entraînement et les pipelines multi-modaux. Complète les foundation models discriminatifs / embeddings existants (Clay, AlphaEarth, etc.).

**Actions recommandées**  
1. Lire le paper + project page : https://arxiv.org/abs/2608.01896 et https://kaist-viclab.github.io/GeoCore-9B_site/  
2. Cloner le repo GitHub et tester les weights (ou la démo si disponible) sur un cas de cloud removal ou SAR-to-optical local.  
3. Comparer qualitativement avec des pipelines classiques (ex. : Earth Engine + modèles existants) sur une zone nuageuse connue.

## 2. Densification des agents MCP géospatiaux (HERE, LGND, RustGIS, Google)

**Résumé**  
La vague MCP continue : HERE Location Reasoning est opérationnel en pay-as-you-go sur AWS Marketplace (MCP sur Bedrock AgentCore) pour du raisonnement spatial déterministe (routing, geocoding, trafic, isolines…). LGND Geo expose gratuitement des embeddings Sentinel-2 (10 m, 2017-avril 2026) et NAIP via MCP à Claude/ChatGPT. RustGIS (open-source, pure Rust, desktop + web) intègre un serveur MCP (`rustgis-cli mcp`) permettant aux agents (Claude Code, Cursor, etc.) de piloter l’ensemble du GIS (outils Whitebox/GeoLibre, export, etc.). Google continue d’élargir l’early access à son Geospatial Reasoning Agent + Planetary Prediction Engine (rapport arXiv:2610.15750).

**Pertinence**  
On passe d’outils GIS isolés à des capacités spatiales directement appelables par des agents généralistes. Cela réduit drastiquement la barrière pour des workflows hybrides (LLM + outils spatiaux déterministes) et ouvre des cas d’usage rapides en logistique, monitoring, change detection ou field service sans stack GIS lourd.

**Actions recommandées**  
1. Ajouter au moins un MCP (LGND Geo : https://geo.lgnd.ai/mcp ou RustGIS) dans Claude Desktop / Cursor et tester une requête concrète sur une zone de travail.  
2. Consulter la fiche AWS Marketplace HERE Location Reasoning et tester un mini-routing multi-contraintes.  
3. Suivre les mises à jour RustGIS (v0.2+/v0.3) sur GitHub opengeos/RustGIS et tester le mode web + MCP.

## 3. Hesai Kosmo et spatial intelligence pour l’IA physique (rappel + momentum)

**Résumé**  
Hesai a lancé Kosmo (Kosmo One : caméra spatiale 8K + LiDAR + IMU ; Kosmo World : cloud avec 3D Gaussian Splatting, précision mm). Un scan ~100 m² en ~15 min par un opérateur. Sorties destinées à l’entraînement de robots / world models / digital twins. Partenariats (Galbot, Dexmal, etc.). Positionnement clair : infrastructure de données spatiales haute fidélité pour l’embodied AI.

**Pertinence**  
Le LiDAR et la capture terrain deviennent des fournisseurs directs de « ground truth » pour les world models et la robotique. Pour les praticiens drones/LiDAR/GIS, cela crée des ponts vers la génération de datasets d’entraînement et la simulation.

**Actions recommandées**  
1. Consulter les specs Kosmo sur le site Hesai et les démos 3D Gaussian Splatting.  
2. Expérimenter un pipeline Gaussian Splatting local sur vos propres scans LiDAR/drone pour évaluer le rendu et les exports.  
3. Identifier un cas interne où un twin 3D haute fidélité améliorerait un workflow de simulation ou d’inspection.
